# ELM Workbench / Mercedes R230

Локальная Node.js-программа для MacBook, Mercedes-Benz SL500 R230 2002 и
Kingbolen ELM327 v1.5 Wi-Fi (заявлен PIC18F25K80). Интерфейс на русском,
без npm-зависимостей, CDN, облака и доступа в интернет.

**Текущая версия НЕ читает ошибки PSE, сидений, COMAND, чейнджера или ABC.**
Она проверяет адаптер, фиксирует принятие настроек ISO/KWP, напряжение, исходный
обмен и помогает собрать наблюдения/фотографии за один сеанс. Для реального
чтения кузовных ЭБУ ещё нужны проверенная физическая диагностическая линия и
профиль Mercedes. Из версии ELM и ответов `OK` их определить нельзя. Поход к
машине только ради этой проверки не гарантирует приближения к чтению ошибок;
сам адаптер можно проверить на столе при внешнем питании.

## Запуск программы

Нужен Node.js 22 или новее. Установка npm-пакетов не требуется.

В этой папке:

```sh
node server.mjs
```

Откройте [локальный интерфейс](http://localhost:8787/).
Сервер слушает **только 127.0.0.1**. Закрытие вкладки не останавливает сервер.
В терминале `Ctrl+C` завершает программу и соединение с ELM.

## Проверка дома без ELM

Одной командой можно поднять UI и отдельный TCP mock:

```sh
node demo.mjs
```

Откройте [демо](http://localhost:8787/?source=mock), нажмите «Подключить и проверить».
Mock действительно общается с клиентом через TCP на `127.0.0.1:35000`.
Ответы помечены как синтетические в интерфейсе и отчёте.

Или запускайте процессы отдельно в двух терминалах:

```sh
node mock-elm.mjs
node server.mjs
```

В UI выберите «Mock · без машины». Mock повторяет ASCII/CR/`>`/echo-формат
реального ELM, но не гарантирует точное воспроизведение всех особенностей клона.
За основу взяты транспортные шаблоны из Flutter ELM-клиента и Dart-эмулятора
проекта; VAG/CAN-адреса Audi и их ответы в Mercedes-профиль не переносятся.

Сценарии mock (запускайте один mock одновременно):

```sh
node mock-elm.mjs --scenario clone
node mock-elm.mjs --scenario no-prompt
node mock-elm.mjs --scenario disconnect
node mock-elm.mjs --scenario low-voltage
node mock-elm.mjs --scenario slow
node mock-elm.mjs --port 35001
```

- `clone`: часть необязательных команд возвращает `?`.
- `no-prompt`: ответ идентификации не заканчивается `>`, клиент закрывает TCP.
- `disconnect`: соединение обрывается на восьмом запросе, частичный отчёт остаётся.
- `low-voltage`: синтетическое напряжение 11,5 В.
- `slow`: замедленные ответы.

## С настоящим адаптером

1. Подготовьте программу и проверьте её на mock до выхода из дома.
2. ELM вставлен в OBD, машина стоит, зажигание включено, двигатель заглушён.
3. Закройте Car Scanner и другие клиенты ELM. Подключите Mac к Wi-Fi адаптера.
   Отсутствие интернета в этой сети нормально.
4. Запустите `node server.mjs`, откройте UI. Выберите «Мой ELM» и «В автомобиле».
   Обычно адрес `192.168.0.10`, порт `35000`; они редактируются.
5. «Подключить и проверить» — короткий, конечный прогон из 22 AT-команд.
   Ожидаемое время — секунды/десятки секунд, а не 40-минутный дамп. При первом
   таймауте прогон прекращается. Фактическое время на Kingbolen ещё не проверено.
6. Заполните наблюдения по нужным системам, приложите фото. «Обновить» возле
   напряжения делает ровно одно измерение, постоянного опроса нет.
7. «Скачать пакет ZIP». Нажмите «Стоп», выключите зажигание, выньте ELM.

При первом обращении macOS может запросить доступ Terminal/Node к локальной
сети. При запрете доступа соединение с ELM не установится.

## На столе с настоящим ELM

Подключите ELM к отдельному стабилизированному питанию **12 В DC** через
проверенный кабель питания OBD-II female. На OBD-разъёме контакт 16 — плюс,
4/5 — земля. Сверьте нумерацию и полярность кабеля; не путайте с выводами чипа.
Обычный USB 5 В напрямую не заменяет 12 В на OBD. Питания 12 В / 1 А достаточно
с запасом для адаптера. Вскрывать корпус или подавать питание на контакты связи
не требуется.

Выберите в UI «Мой ELM» → «На столе · внешнее питание 12 В».
Wi-Fi и AT-проверка работают без автомобильных ЭБУ. Такой отчёт получает явную
пометку «стол»: это не диагностика автомобиля.

## Что собираем по кузову

- PSE: замки, доводчик, наблюдаемая работа насоса при обычном использовании.
- Мультиконтур слева/справа: индикация PULSE, щелчки, накачивание/шипение,
  различия сторон.
- Электросиденья: конкретные неработающие направления, память.
- COMAND / CD: точный текст ошибок, работа радио и звука, реакция чейнджера.
- ABC: сообщения и цвет предупреждения, положение машины после стоянки.

Программа не предлагает разбирать блоки, отключать предохранители, перемыкать
контакты, проверять давление или запускать тесты подвески.
Наблюдения пользователя отделены от аппаратных измерений.

## Данные и экспорт

`data/<сеанс>/report.json` — структурированный отчёт; `events.jsonl` — исходный
обмен с временными метками; фотографии — рядом. JSON сохраняется атомарно,
журнал дописывается после событий. Незавершённый прогон при следующем запуске
получает статус `interrupted`. Архив доступен через интерфейс после перезапуска.

ZIP содержит `report.json`, `events.jsonl`, `README.txt` и `photos/`.
Он открывается стандартным архиватором. Даже после обрыва ELM можно заполнить
наблюдения и скачать частичный пакет. Фотографии: JPEG/PNG/WebP, до 5 МБ каждая,
не более 12 на сеанс.

VIN можно заполнить в UI. Для локального значения по умолчанию создайте
`data/vehicle.json` с объектом `{"vin":"ваш VIN из 17 символов"}`. Runtime-данные,
включая VIN и фото, исключены из Git. В раздаваемый архив программы они не входят.

## Ограничения и защита

- Единственная точка записи TCP проверяет точный allow-list перед отправкой.
- Разрешены только фиксированные команды настройки/чтения самого адаптера.
  Ни один диагностический payload ЭБУ не разрешён, включая стандартный OBD.
- Нет свободного терминала, произвольных заголовков, входа в сессии Mercedes,
  очистки DTC, SecurityAccess, программирования, адаптаций, калибровок или активаций.
- `ATZ` перезапускает **адаптер ELM**, не автомобильный ЭБУ. `ATTP` проверяет
  принятие настройки протокола без отправки автомобильного запроса.
- В полёте одна команда; максимальный ответ 32 КБ; при таймауте TCP закрывается.
  Голый CR для повтора/ресинхронизации не посылается. Автоматических повторов нет.
- UI только на loopback, API проверяет origin/host и токен изменения состояния.
- Только частные IPv4-адреса ELM или loopback mock; публичные IP/hostnames запрещены.

Это уменьшает риск со стороны программных действий. Качество, разводку и
электрическую исправность неизвестного экземпляра адаптера программа не проверяет.
Испытаний на реальном автомобиле ещё не было.

## Проверки

```sh
node --test test/*.test.mjs
```

Тестируются настоящий TCP mock, фрагментация, эхо, очередь, таймаут, остановка,
обрыв связи, запрет команд и инъекций, частичные отчёты, фото, ZIP, перезапуск,
локальное HTTP API. На mock также вручную проверяется браузерный сценарий.

## Источники

- [ELM327 — документация производителя](https://www.elmelectronics.com/wp-content/uploads/2020/05/ELM327DSL.pdf): AT-команды, Protocol Close / Try Protocol, электрическая схема.
- [Mercedes-Benz USA — R230 System Diagnosis (копия учебного материала)](https://pdfcoffee.com/318-ho-syst-diag-gcjljm-01-09-03-pdf-free.html): архитектура раннего R230, роль EIS/N55 и разделение систем.
- [iCarsoft — таблица функций Mercedes](https://www.icarsoft.com/Uploads/download/MB%20V1.0%26M900%20V1.0_Benz_V01.05%20Fuction%20List.pdf): PSE и OSB-FL/FR для SL230 до 08/2003. Это подтверждение наличия диагностики у специализированного сканера, не совместимости ELM.
